Kappa Gate · фильтр галлюцинаций для RAG

Нет контекста, нет ответа.

Антигаллюцинаторный шлюз для базы знаний. Каждому утверждению присваивается целочисленный контекст K. В ответ модели попадает только K ≥ 1. Парадоксы и непроверенные утверждения получают K = 0 и уходят в карантин.

Проверить на прочность Загрузить документы
Nebius Token FactoryNVIDIA NemotronTavily Search

Сделано для Nebius × NVIDIA Global AI Hackathon. Nemotron на Nebius Token Factory размечает запрос и формулирует ответ, Tavily приносит свежие доказательства, а что допустить в ответ, решает K-движок.

Принцип работы

Три корзины вместо одной свалки

Обычный RAG кладёт в промпт всё, что нашёл. Шлюз сначала сортирует найденное по уровню доверия и пропускает к модели только проверенное.

T · K ≥ 1

Проверено

Подтверждённые факты. Только они попадают в ответ, и у каждого утверждения есть ссылка на источник.

U · K = 0

Неизвестно

Парадоксы, самоссылки и непроверенные данные. Шлюз честно отвечает: информации нет.

F · K ≤ −1

Опровергнуто

Заведомо ложное. Блокируется и не доходит до модели, даже если очень похоже на ответ.

Панель управления

База знаний с операторами K

Это данные, по которым работает фильтр. Загрузите документы, и K посчитается по источникам, или зарегистрируйте факт вручную. Точки на числовой прямой на главной двигаются вслед за K.

Загрузка документа

Превратите текст компании в базу знаний

Вставьте регламент, прайс или инструкцию. Документ делится на факты, и K считается автоматически: каждый независимый источник добавляет свой вес, повторное подтверждение из другого источника повышает K, противоречие от надёжного источника его снижает.

Факты из документа появятся здесь

Ручная регистрация факта (S)

Обычно K считается сам при загрузке документов. Здесь K можно задать вручную.

K ≥ 1 ⟹ S ∈ T  ·  K ≤ −1 ⟹ S ∈ F  ·  K = 0 ⟹ S ∈ U

Динамическая эволюция (ΔK)

K(t₁) + ΔK = K(t₂)

Если у утверждения есть ссылки и оно образует парадокс, Аксиома 4 вернёт K = 0 даже после ΔK.

Интеграция в ваш RAG

Шлюз между базой знаний и моделью

Решение о допуске принимает детерминированный движок, а не языковая модель. Модель только размечает запрос и формулирует ответ из уже допущенных фактов. Любое утверждение ответа без ссылки на факт с K ≥ 1 удаляется.

ИИРазбор запросаВыделяет утверждения, их самоссылки и подходящие факты. Истинность не оценивает.
ДвижокОценка KАксиома 4 проверяет самоссылки. Факты делятся на T, F, U.
ДвижокФильтр контекстаВ промпт идут только факты с K ≥ 1. F и U не покидают шлюз.
ИИГенерацияОтвечает только по допущенным фактам и указывает id источника для каждого утверждения.
ДвижокВерификацияУдаляет утверждения без ссылки или со ссылкой на факт не из T.
РезультатОтвет или K = 0Либо ответ из T, либо явное «информации нет».

      Как запустить живой поиск
      
    
        
  1. Получите ключ Nebius Token Factory и ключ Tavily. Сохраните файлы contextual_gateway.py, cl_ml.py, cl_model.json, tavily_source.py, live_gateway.py, llm_adapters.py в одну папку.
    2. 
        
  2. Задайте ключи: export NEBIUS_API_KEY=… и export TAVILY_API_KEY=tvly-….
    3. 
        
  3. Выполните: python live_gateway.py "Столица Узбекистана — Ташкент?" --provider nebius. Или запустите весь сайт командой python server.py и выберите «Живой поиск · Tavily» на стенде.
    4. 
      

    

    
Три режима работы. База знаний: сайт отвечает по вашим документам и фактам. Живой поиск: на каждый вопрос сервер ищет в интернете через Tavily, превращает страницы в факты (каждый домен один источник, его класс задаёт вес в K) и пропускает их через тот же шлюз; ничего не сохраняется. Гибрид (hybrid_gateway.py): оба вместе, с отдельным списком противоречий между вашей базой и интернетом. Модели Nemotron работают на Nebius Token Factory, ключи API остаются на сервере.

    
Источники из Wikidata. Модуль external_sources.py берёт утверждения Wikidata вместе с их ссылками и сохраняет файл состояния: каждая ссылка считается одним источником. Его можно импортировать ниже или использовать в ask.py. Он запускается у вас на компьютере. Что шлюз гарантирует: в ответ попадают только факты с K ≥ 1 из вашей базы, самореферентные запросы блокируются. Чего не гарантирует: верность самих значений K. Их задаёт источник данных (люди, правила, рейтинг источников). Обновляйте K через ΔK, когда приходят новые данные.
